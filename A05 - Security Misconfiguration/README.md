# ⚙️ A05: Security Misconfiguration

---

## 📌 1. Definition (التعريف الاحترافي)

هي ثغرات أمنية ناتجة عن عدم ضبط أو تأمين إعدادات السيرفر (Server) او التطبيقات أو الخدمات السحابية بشكل صحيح , تحدث عندما تُترك الإعدادات الافتراضية (Default Settings) كما هي، أو يتم تفعيل ميزات غير ضرورية تفتح أبواباً للمخترقين.

---

## 🧠 2. Real-World Analogy (مثال واقعي لفهم الثغرة)

تخيل أنك اشتريت أفضل وأغلى **بيت** 🏠 في العالم:

---

### ✅ الوضع المثالي

عندك **قفل** (Firewall/Encryption) أصلي وممتاز جداً.

---

### ❌ الخلل (The Misconfiguration)

- تركت **الباب مفتوحاً** 🚪 (نسيان إغلاق بورتات غير مستخدمة).
        
- أو قفلت الباب لكنك **نسيت المفتاح** في القفل من الخارج 😅 (كلمات مرور افتراضية).
        
- أو وضعت المفتاح تحت السجادة أمام الباب (ملفات إعدادات مكشوفة).

---

### ⚠️ النتيجة

المشكلة هنا ليست في جودة "القفل" (الكود أو التشفير)،  
القفل يعمل بنسبة 100%.

---

## 🧩 3. Types (أشهر أنواع أخطاء الإعدادات)

---

### 🔹 Debug Mode (وضع التصحيح) مفعّل

بدلاً من إظهار صفحة خطأ بسيطة، يعرض الموقع معلومات تقنية دقيقة.

💥 **الخطر:**  
يكشف عن مسارات الملفات (Paths)، إصدارات البرامج، وأحياناً مفاتيح سرية (Secrets).

---

### 🔹 Directory Listing (عرض المجلدات) مفتوح

عندما تدخل لرابط مجلد مثل:

```text
/uploads/
/images/
```

💥 **الخطر:**  
السيرفر يعرض لك قائمة بكل الملفات الموجودة بداخله وكأنك في جهازك الشخصي، مما قد يكشف ملفات حساسة.

---

### 🔹 Default Credentials (بيانات الدخول الافتراضية)

ترك لوحات التحكم بكلمات مرور المصنع مثل:

```text
admin:admin
root:1234
```

💥 **الخطر:**  
دخول مباشر وبصلاحيات كاملة دون أي عناء.

---

### 🔹 Security Headers (الرؤوس الأمنية) ناقصة

غياب التعليمات التي يرسلها السيرفر للمتصفح لحمايته، مثل:

- `X-Frame-Options` → للحماية من الـ Clickjacking
        
- `Content-Security-Policy (CSP)` → للحماية من الـ XSS

---

### 🔹 Open Ports (الخدمات المفتوحة)

ترك منافذ (Ports) مفتوحة لخدمات لا يجب أن تكون عامة، مثل:

```text
SSH
FTP
Database Ports
```

---

### 🔹 معلومات حساسة في الكود (Hardcoded Secrets)

وجود مفاتيح الـ API Keys أو كلمات مرور قاعدة البيانات مكتوبة بوضوح داخل ملفات الـ JavaScript أو ملفات الإعدادات المكشوفة.

---

### 🔹 CORS Misconfiguration

إعدادات مشاركة الموارد (CORS) تسمح لأي موقع غريب بطلب بيانات المستخدمين من السيرفر.

---

## 🔥 4. Impact (ليش هي خطيرة؟)

تعتبر **Security Misconfiguration** من أكثر الثغرات التي تسبب صداعاً لفرق الأمن السيبراني لأنها:

---

### 😈 سهلة الاكتشاف

هناك أدوات آلية بسيطة جداً (Scanners) يمكنها اكتشاف الإعدادات الخاطئة في ثوانٍ،  
مثل البورتات المفتوحة أو كلمات المرور الافتراضية.

---

### 🌎 منتشرة جداً

بسبب تعقيد الأنظمة الحديثة:

- سيرفر
- قاعدة بيانات
- Cloud
- تطبيقات

من السهل جداً على المهندس أن ينسى إغلاق ثغرة واحدة في إحدى هذه الطبقات.

---

### 🔑 أحيانًا تعطيك وصول مباشر

في كثير من الأحيان، لا يحتاج المخترق لكتابة "كود خبيث"؛  
فقط يدخل بكلمة المرور الافتراضية أو يجد ملف إعدادات مكشوفاً يحتوي على مفاتيح الدخول،  
مما يعطيه صلاحيات كاملة فوراً.

---

## 🛠️ 5. Discovery (كيف تكتشفها؟)

عملية الاكتشاف تعتمد على الاستطلاع الذكي (**Recon**) والتدقيق في التفاصيل:

---

### 🕵️ تصفح الموقع كامل

لا تكتفِ بالصفحة الرئيسية.

ابحث في:
- الروابط
- الملفات
- السكربتات
- طريقة ترابط الصفحات

---

### 🔍 جرب الروابط الحساسة (Fuzzing / Directory Brute Force)

ابحث عن المجلدات والملفات التي قد تكون متروكة بالخطأ، مثل:

```text
/admin
/administrator
/backup
/.git
/test
/dev
/phpinfo()
```

---

### 🛡️ استخدم Burp Suite

التقط الطلبات (Requests) وحلل الردود (Responses) القادمة من السيرفر.

ابحث عن:
- معلومات مسربة
- أخطاء تقنية
- بيانات حساسة داخل الـ Response Body

---

### 📝 افحص الـ Headers

راجع الـ HTTP Headers بدقة:

- هل السيرفر يكشف نوعه وإصداره؟
        
- هل هناك Headers أمنية ناقصة؟
        
- هل توجد معلومات داخلية مثل:
        
```text
X-Powered-By
Server
```

---

## 🛡️ 6. Remediation (كيف تُصلح؟)

الإصلاح هنا يعتمد على مبدأ **Hardening** (تقوية النظام) وتقليل مساحة الهجوم.

---

### 🚫 إيقاف الـ Debug Mode

يجب تعطيل وضع التصحيح في بيئة العمل الحقيقية (Production).

استبدل رسائل الخطأ التفصيلية بصفحات خطأ عامة لا تكشف معلومات تقنية.

---

### 🔒 إغلاق الخدمات غير المستخدمة

أي بورت (Port) أو خدمة (Service) لا يحتاجها الموقع للعمل يجب إغلاقها فوراً.

#### 📌 مثال

```text
إغلاق بورت 3306 الخاص بقواعد البيانات عن العالم الخارجي
```

---

### 🛡️ إضافة Security Headers

تفعيل الرؤوس الأمنية القوية لإخبار المتصفح بكيفية التعامل مع الموقع بأمان.

#### 📌 أمثلة

```text
Content-Security-Policy
X-Frame-Options
Strict-Transport-Security
```

---

### 🙈 إخفاء المعلومات الحساسة

- تغيير كلمات المرور الافتراضية فوراً.
        
- تعطيل خاصية `Directory Listing`.
        
- إزالة أي Secrets أو API Keys من الكود البرمجي.
        
- استخدام Environment Variables لحماية البيانات الحساسة.

---

## 🧠 7. Attacker Mindset (كيف تفكر كمخترق؟)

في هذه الثغرة، أنت لا تهاجم الكود، بل تهاجم "بيئة العمل".

---

### 🧐 هل فيه معلومات زيادة؟

"هل السيرفر يتكلم كثيراً؟  
هل يعطيني إصدارات البرامج أو Paths داخل رسائل الخطأ؟"

---

### 🕵️ هل في صفحات مخفية؟

"هل المبرمج نسي صفحة مثل:

```text
/admin
/config
/test.php
```

أو هل يوجد Directory Listing مفعّل؟"

---

### 🔓 هل في إعدادات مفتوحة؟

"هل بورت قاعدة البيانات مفتوح؟  
هل لوحة التحكم تستخدم كلمات مرور افتراضية؟"

---

### 😈 هل السيرفر مرتاح زيادة؟

"هل السيرفر يسمح بأي نوع من الطلبات؟  
هل يثق بأي Domain يطلب بيانات؟"

السيرفر "المرتاح" غالباً يكون غير مؤمن 😈
