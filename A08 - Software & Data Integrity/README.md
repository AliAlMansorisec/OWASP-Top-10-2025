# 🧬 A08: Software and Data Integrity Failures

## 📌 1. Definition (التعريف)

> **هو فشل النظام في التحقق من سلامة البرامج والبيانات، مثل الاعتماد على تحديثات أو مكتبات من مصادر غير موثوقة دون التحقق من صحتها، أو عدم حماية البيانات من التعديل غير المصرح به، مما يسمح للمهاجم بتغيير البيانات أو إدخال برامج ضارة.**

---

## 🧩 2. Types (أنواع الثغرة)

- **تحديثات غير موقعة (Unsigned Updates)**: تحميل تحديثات من الإنترنت بدون التحقق من التوقيع الرقمي أنها من المصدر الرسمي.
    
- **مكتبات من مصادر غير موثوقة (Untrusted Libraries)**: استخدام مكتبات من GitHub شخصي أو مواقع غير رسمية بدون فحص.
    
- **خط أنابيب CI/CD غير آمن (Insecure CI/CD Pipeline)**: إمكانية حقن كود ضار أثناء عملية البناء والنشر الآلي.

- **التلاعب بالبيانات أثناء الإرسال (Data Tampering in Transit)**: قبول بيانات من المستخدم بدون التحقق من سلامتها، مثل تعديل سعر منتج من 10$ إلى 1$ أثناء الطلب
    
- **إلغاء تسلسل كائنات غير آمن (Insecure Deserialization)**: إرسال كائن مبرمج (مثل Java أو PHP) معدل بطريقة ضارة، وعند تحويله من قبل النظام يتم تنفيذ كود غير مصرح به.
---

## 🛡️ 4. How to Prevent (كيف تمنعها)

- **التحقق من التوقيع الرقمي (Digital Signatures):** تأكد من أن أي تحديث أو مكتبة يتم تحميلها من الإنترنت موقعة رقمياً من المصدر الرسمي قبل تثبيتها.
    
- **استخدام المصادر الموثوقة فقط:** لا تقم بتحميل مكتبات أو أدوات من GitHub شخصي أو مواقع غير رسمية؛ استخدم المستودعات الرسمية مثل NPM أو Maven أو PyPI.
    
- **تأمين خط أنابيب CI/CD:** قم بحماية عملية البناء والنشر الآلي، وتأكد من أن أي تغيير في الكود يمر بمراجعة أمنية قبل النشر.
    
- **التحقق من سلامة البيانات أثناء الإرسال:** استخدم التواقيع الرقمية أو قيم Hash للتحقق من أن البيانات لم يتم التلاعب بها أثناء النقل (مثل تعديل سعر المنتج).
    
- **تجنب إلغاء التسلسل (Deserialization) من مصادر غير موثوقة:** لا تقبل كائنات Java أو PHP أو Python من مستخدمين غير موثوقين؛ استخدم صيغاً بسيطة مثل JSON مع التحقق من صحتها.
    
- **تفعيل Integrity Checks في التطبيق:** قم بمقارنة قيم Hash للملفات المهمة بشكل دوري للتأكد من عدم تعديلها.
    
- **استخدام أدوات فحص السلامة:** استخدم أدوات مثل `OWASP Dependency-Check` أو `Snyk` لاكتشاف المكونات التي قد تحتوي على مشاكل تكامل.
---
## 🧠 Attacker Mindset (كيف تفكر كمخترق؟)

- **هل التحديثات تتحمل من رابط بدون `https://`؟** كيف أقدر أحقن تحديث ضار؟
- **هل البيانات (زي سعر المنتج) ترسل من العميل بدون التحقق؟** كيف أغير السعر من 10$ إلى 1$ أثناء الطلب؟
- **هل التطبيق يستخدم JWT؟** كيف أحاول أعدل التوقيع وأشوف إذا النظام يقبله؟
---
### 🔀 Sub-Vulnerabilities (ثغرات متفرعة ضمن هذا التصنيف)

- **Race Conditions (سباق الظروف)**: استغلال التوقيت بين عمليتين متتاليتين لتنفيذ أمر غير مصرح به.
