# 🔐 A02: Cryptographic Failures

---

## 📌 1. Definition (التعريف)


> **هو فشل النظام في حماية البيانات الحساسة باستخدام التشفير الصحيح او عدم استخدام تقنيات تشفير قوية أو استخدامه بطريقة خاطئة.**.
---

## 🧩 2. Types (أنواع الثغرة)

- **خوارزمية ضعيفة (Weak Algorithm)**: استخدام MD5 أو SHA1 أو DES بدل الخوارزميات القوية مثل AES-256.
    
- **تشفير يدوي مخترق (Homegrown Crypto)**: المبرمج يخترع طريقة تشفير خاصة به بدل استخدام مكتبات موثوقة.
    
- **عدم استخدام تشفير (No Encryption)**: إرسال البيانات الحساسة نص عادي (Plaintext) عبر الشبكة.
    
- **مفاتيح ثابتة أو مخزنة في الكود (Hardcoded Keys)**: تخزين مفتاح التشفير داخل الكود المصدري نفسه.
    
- **نقل بيانات بدون TLS (Missing TLS)**: مثل إرسال كلمة المرور عبر HTTP بدلاً من HTTPS.
    
- **تخزين مفاتيح غير آمن (Insecure Key Storage)**: حفظ المفاتيح في ملفات نصية أو قاعدة بيانات بدون حماية.
---

## 🛡️ 4. How to Prevent (كيف تمنعها)

- **استخدام HTTPS فقط:** تأكد من أن الموقع بالكامل يعمل عبر `https://` وليس `http://`، وقم بتفعيل HSTS لفرض الاتصال الآمن.
    
- **تشفير البيانات الحساسة في التخزين:** لا تقم بتخزين كلمات المرور أو أرقام البطاقات أو المفاتيح السرية بصيغة نص عادي في قاعدة البيانات.
    
- **استخدام خوارزميات تشفير قوية ومعتمدة:** مثل AES-256 للبيانات، وbcrypt أو Argon2 لكلمات المرور، وتجنب نهائياً MD5 أو SHA1.
    
- **إدارة المفاتيح بشكل آمن:** لا تخزن مفاتيح التشفير داخل الكود المصدري أو ملفات `.env` بشكل نص عادي، استخدم أدوات مثل AWS KMS أو HashiCorp Vault.
    
- **عدم اختراع خوارزمية تشفير خاصة:** لا تحاول تصميم طريقة تشفير بنفسك، استخدم المكتبات الموثوقة والمعترف بها عالمياً.
    
- **تأمين النقل (TLS):** تأكد من استخدام إصدارات حديثة من TLS (مثل TLS 1.2 أو 1.3) وتعطيل الإصدارات الضعيفة مثل SSLv3 و TLS 1.0.
---


## 🧠 Attacker Mindset (كيف تفكر كمخترق؟)

- **هل البيانات تنتقل عبر HTTP ولا HTTPS؟** كيف أقدر اعترضها واقرأها؟
- **هل كلمة المرور تخزن بصيغة MD5 أو SHA1؟** كيف أقدر أفك تشفيرها؟
- **هل فيه ملفات مثل `.env` أو `config.php` مسربة؟** كيف القاها وأشوف مفاتيح التشفير؟
- **هل التشفير مصمم بشكل يدوي؟** كيف أقدر أكتشف ثغرات فيه؟"
